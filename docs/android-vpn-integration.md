# Android VPN-модуль CyberVPN

## Архитектура

`modules/cybervpn-vpn` — локальный Expo-модуль только для Android. `CyberVpnModule` открывает системный диалог `VpnService.prepare()`, передаёт выбранную ссылку `hy2://` в foreground-сервис и сообщает JS фактическое состояние из системного хранилища. `CyberVpnService` создаёт TUN через `VpnService.Builder`, применяет IPv4 default route, IPv6 default route при включённом IPv6 и DNS-адреса Hysteria; защищает сокеты ядра через `VpnService.protect(fd)`. Состояние «подключено» устанавливается только после успешного старта клиента Hysteria.

Hysteria URI разбирается нативным парсером Bedlam (`parseHysteriaUri`); исходный URI не передаётся в shell и не сохраняется приложением дополнительно. Конфигурации остаются в существующем локальном кэше репозитория, который уже использует приложение.

## Приватность и обход доменов

Адреса TUN `172.19.0.1` и `fdfe:dcba:9876::1` — внутренние адреса виртуального интерфейса, а не публичный адрес VPN-выхода. `VpnService.protect(fd)` защищает сокеты самого Hysteria-клиента от попадания в собственный туннель; это не скрывает факт VPN от других Android-приложений. Приложения могут определить VPN-транспорт средствами Android, а внешний сервис увидит публичный IP выхода, если приложение обратится к нему через туннель и запросит этот адрес.

При активном профиле маршруты `0.0.0.0/0` и `::/0` направляют весь IPv4- и IPv6-трафик через VPN. Внизу экрана есть выключенный по умолчанию переключатель `NoToVPN`, раздельные редактируемые списки доменных зон и сайтов, а также opt-in действие добавления 287 активных country-code TLD IANA (включая территории и IDN). Зоны `.ru`, `.kz`, `.eu` и официальный российский сайт-лист являются стартовыми настройками, но не включают NoToVPN автоматически. Изменение включённого списка вызывает `HysteriaClientImpl.updateTun()` и заменяет TUN-конфигурацию без нового QUIC-подключения. Отказ обновления считается ошибкой и завершает туннель, чтобы экран не сообщал об успешно применённых исключениях. Общий лимит — 400 правил.

Go-ядро нормализует имена через IDNA. Запись `.ru` либо `*.ru` совпадает с `example.ru` и его поддоменами, но не с `notru` или `example.rust`; запись без начальной точки остаётся точным совпадением. DNS-запросы выбранных имён отправляются через Direct DNS: DNS активной физической сети, Android Private DNS по DoT при доступном имени сервера либо зашифрованный Cloudflare DoH fallback. Если прямой DNS не настроен или не отвечает, ядро возвращает SERVFAIL и не переключает выбранное имя на DNS через Hysteria. A/AAAA и CNAME-ответы дают ограниченные TTL записи IP; только потоки к свежим IP из реестра направляются protected/direct TCP/UDP, остальные остаются в Hysteria.

Обычный DNS настраивается на экране отдельно: UDP, TCP, DoT или DoH и от 1 до 8 upstream-адресов. Настройки проверяются JS и Kotlin, передаются Expo bridge в Android foreground service и задаются через `TunConfig.dns`; Kotlin wire-конвертер отправляет Go-ядру транспорт, список upstream и on-TUN listen-адреса. Go выполняет последовательный staggered failover и может временно предпочесть upstream, который ответил. Для обычного DNS нет скрытого прямого физического fallback. При подключённом туннеле экран сохраняет DNS-настройку для следующего переподключения.

Это DNS-aware IP routing, а не точный доменный firewall. Совместно используемый CDN-IP может временно идти напрямую и для других доменов до истечения DNS lease; приложение с собственным DoH/DoT, зашифрованным DNS или кешированным IP может не раскрыть имя VPN-модулю. Провайдер Direct DNS видит выбранные DNS-запросы. Подтверждение реального Android-туннеля и маршрутов требует native build и проверки на устройстве.

## Сборочная среда

Android minSdk поднят до 29. Gradle `preBuild` вызывает `buildHysteriaAar`, который при необходимости загружает Go `1.26.8`, подготавливает pinned Hysteria source tree и выполняет gomobile bind для `arm64-v8a` и `armeabi-v7a`. Ожидаются переменные `ANDROID_HOME` или `ANDROID_SDK_ROOT` и `ANDROID_NDK_HOME` (если NDK не указан явно, скрипт ищет самую новую side-by-side версию в `$ANDROID_HOME/ndk`). AAR является генерируемым файлом и исключён из Git.

## Ограничение подтверждения

Cloud Sandbox не содержит Android SDK/NDK, Go, ADB, эмулятора или подключённого Android-устройства. На этой стадии не выполнены native Gradle build, выдача Android permission в реальном системном диалоге, подключение к рабочему серверу и проверка маршрутизации реального пользовательского трафика. Не заявляйте, что APK уже собран или сквозной туннель подтверждён, пока Android-сборка и устройство не проверены.


## Сверка DNS-модели с hy2tui

README проекта [sociocyber1/hy2tui](https://github.com/sociocyber1/hy2tui) описывает отдельный список пользовательских DNS-серверов, применяемый внутри туннеля, с приоритетом, проверкой скорости и live-update; для доменов NoToVPN там отдельно указан `direct_dns`. README также описывает быстрый выбор ответа: сначала основной резолвер, затем остальные с интервалом 300 мс; побеждает первый ответ. Это использовано как архитектурный ориентир, а не как гарантия измеренной скорости на сети CyberVPN.
